# Languages and i18n

## How the bilingual setup works

- Each language has its own content tree (`content/en/`, `content/fr/`) declared via `contentDir` in `hugo.toml`. Pages with the same path are translations of each other.
- The default language (`defaultContentLanguage = 'en'`) is served at `/`; others get a prefix (`/fr/...`).
- Each language block in `hugo.toml` carries its own menu and its own `subtitle`/`description` params.
- All UI strings live in `i18n/en.toml` and `i18n/fr.toml`. Layouts never hardcode copy.
- The nav language switch links to the current page's translation when one exists, and to the other language's home page otherwise. `hreflang` alternates are emitted for every translated page.
- The command palette includes a "read in English" / "lire en français" command (`cmd_lang` string).

## Customizing the copy

The homepage hero, the entire about page, the footer, tooltips, and the console easter egg are i18n strings. Grep for the commented groups (`# Homepage`, `# About`, `# Footer`, `# Cursor tooltips`, `[egg_message]`). Some strings are rendered with `safeHTML` and may contain markup - the hero title uses `<span class="pixel">` and `<span class="serif">` accents you can reuse.

Setting `egg_message` to an empty string disables the console easter egg.

## Adding a language

1. Copy a language block in `hugo.toml` (e.g. `[languages.de]`), set `languageCode`, `languageName`, `weight`, `contentDir = 'content/de'`, and translate the menu.
2. Create `i18n/de.toml` by copying `i18n/en.toml` and translating the values.
3. Create `content/de/` mirroring the page files of `content/en/` (`about.md`, `archives.md`, `cves.md`, `links.md`, `slides.md`, `posts/_index.md`).
4. Optional: add the language-prefixed paths (`/de/`, `/de/posts/`, ...) to the `$bgPages` slice in `themes/pouet/layouts/_default/baseof.html` if you want the pixel-canvas background on those pages.

## Removing a language (going monolingual)

1. Delete the `[languages.fr]` block from `hugo.toml`.
2. Delete `content/fr/`.
3. Optionally delete `i18n/fr.toml` and prune the `/fr/...` entries from `$bgPages` in `baseof.html`.

The language switch renders nothing when only one language exists; no template surgery needed.

## French style notes

The shipped FR strings follow a few conventions worth keeping if you write in French: feminine agreement for technical nouns where natural ("une vulnérabilité"), no anglicisms where a French verb exists ("imposer", not "enforcer"), CVSS labels and technical acronyms untranslated, and the same casual tone as the English.
